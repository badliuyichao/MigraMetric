# 异构系统升迁工作量评估系统 - 需求说明文档

## 一、项目概述

### 1.1 项目背景
企业长期使用ERP系统，现采购新的ERP系统，需要将旧系统的历史数据迁移到新系统。本系统旨在建立一个Web工具，用于评估异构ERP系统数据迁移的工作量，为客户提供量化、可视化的评估报告。

### 1.2 项目目标
- 建立科学的工作量评估模型
- 提供便捷的Web工具进行工作量评估
- 输出详细的工作量评估报告
- 支持多维度统计分析

### 1.3 目标用户
| 用户角色 | 职责说明 |
|---------|---------|
| 系统管理员 | 配置系统基础数据：系统类型、模块库、阶梯参数、加权系数等 |
| 评估用户 | 创建评估项目、执行工作量评估、查看统计结果、导出评估报告 |

## 二、核心业务流程

### 2.1 整体业务流程
```
管理员配置基础数据 → 用户创建评估项目 → 填写评估指标 → 系统计算工作量 → 查看统计结果 → 导出评估报告
```

### 2.2 用户操作流程
1. **创建评估项目**：填写项目基本信息（项目名称、客户名称、源系统、目标系统等）
2. **选择迁移模块**：从模块库选择需要迁移的模块，可调整模块加权系数
3. **填写评估指标**：录入数据量、用户数、报表数、客开情况等指标
4. **系统自动计算**：根据评估模型自动计算工作量
5. **查看统计结果**：多维度查看工作量统计
6. **导出评估报告**：导出详细的工作量评估表

## 三、功能需求详细说明

### 3.1 系统管理模块（管理员）

#### 3.1.1 系统管理
**业务场景**：管理员需要维护ERP系统类型信息，为评估项目提供系统选择。

**功能描述**：
- 管理升迁涉及的ERP系统类型（如：SAP、Oracle、用友、金蝶等）
- 系统分为源系统和目标系统两类
- 支持一对一的升迁场景（不支持系统组合）

**功能要点**：
- 新增系统类型（系统名称、系统类型、描述）
- 编辑系统类型信息
- 启用/禁用系统类型
- 删除未被项目使用的系统类型
- 查看系统类型列表

#### 3.1.2 模块库管理
**业务场景**：管理员需要维护各ERP系统的标准模块及其基础工作量配置。

**功能描述**：
- 管理各系统的标准模块清单（如：财务管理、供应链管理、生产管理等）
- 配置每个模块的基础人天和默认加权系数
- 同一模块在不同系统中可配置不同的基础人天

**功能要点**：
- 新增模块（模块名称、所属系统、基础人天、默认加权系数、描述）
- 编辑模块信息
- 配置模块基础人天（单位：人天）
- 配置模块默认加权系数
- 启用/禁用模块
- 删除未被项目使用的模块
- 支持模块分类/分组管理
- 查看模块列表（支持按系统筛选）

**示例数据**：
| 模块名称 | 所属系统 | 基础人天 | 默认加权系数 |
|---------|---------|---------|------------|
| 财务管理 | SAP | 15 | 1.2 |
| 财务管理 | 用友 | 12 | 1.0 |
| 供应链管理 | SAP | 20 | 1.5 |
| 生产管理 | SAP | 25 | 1.8 |

**业务场景**：跟踪评估项目的进展状态。

**项目状态定义**：
| 状态 | 说明 |
|------|------|
| 草稿 | 项目创建，未开始评估 |
| 进行中 | 正在评估中，已录入部分指标 |
| 已完成 | 评估完成，报告已生成 |
| 已归档 | 项目归档，只读状态 |

**状态流转规则**：
```
草稿 → 进行中 → 已完成 → 已归档
```
- 进入评估页面时，状态自动变为"进行中"
- 完成评估并生成报告后，状态变为"已完成"
- 项目归档后，状态变为"已归档"，只读不可修改

### 3.3 工作量评估模块

#### 3.3.1 评估流程设计
**业务场景**：用户按照步骤完成工作量评估。

**评估步骤**：

**步骤一：系统确认**
- 显示项目已配置的源系统和目标系统

**步骤二：选择迁移模块**
**功能描述**：
- 从模块库加载该源系统的所有可用模块
- 用户选择需要迁移的模块（多选）
- 显示每个模块的基础人天和默认加权系数
- 支持调整模块的加权系数（项目级别调整，不影响全局配置）

**界面展示要素**：
- 模块列表（复选框选择）
- 模块名称
- 基础人天
- 默认加权系数
- 调整系数输入框
- 最终系数（显示调整后的系数）

**业务规则**：
- 至少选择一个模块
- 调整系数可以大于或小于默认系数
- 如果未调整，使用默认系数

**步骤三：填写评估指标**
**业务描述**：录入各项评估指标数据。

##### 指标1：模块相关信息
- 显示已选模块列表
- 显示每个模块的基础人天和最终系数

##### 指标2：数据库表数量
- 录入需要迁移的数据库表总数量
- 单位：个

##### 指标3：数据量
- 录入数据总量
- 单位：万条
- 系统根据数据量自动匹配数据量阶梯系数

##### 指标4：用户数量
- 录入系统用户总数

- 显示匹配的阶梯名称

##### 指标5：报表数量
- 录入需要迁移的报表总数

- 选择数据清洗复杂度（简单/中等/复杂）
- 注意：数据清洗需求仅作为参考信息，不计入工作量计算

**步骤四：计算工作量**
- 系统根据评估模型自动计算工作量
- 显示计算结果和详细明细

#### 3.3.2 工作量评估模型

**模型概述**：
工作量评估模型包含三个维度：核心迁移工作量、报表工作量、客开工作量。

**总工作量计算公式**：
```
总工作量（人天） = 核心迁移工作量 + 报表工作量 + 客开工作量
```

##### 1. 核心迁移工作量

**计算公式**：
```
核心迁移工作量 = Σ(各模块基础人天 × 模块加权系数 × 数据量阶梯系数 × 用户数阶梯系数)
```

**计算逻辑**：
1. 遍历所有选中的模块
2. 对每个模块计算工作量：
   ```
   模块工作量 = 模块基础人天 × 最终加权系数 × 数据量阶梯系数 × 用户数阶梯系数
   ```
   - **模块基础人天**：从模块库配置获取
   - **最终加权系数**：默认系数或用户调整后的系数
   - **数据量阶梯系数**：根据录入的数据量，系统自动匹配阶梯系数
   - **用户数阶梯系数**：根据录入的用户数，系统自动匹配阶梯系数
3. 累加所有模块的工作量

**计算示例**：
假设：
- 选择了财务管理模块：基础人天15天，调整系数1.3
- 选择了供应链管理模块：基础人天20天，使用默认系数1.5
- 数据量：500万条（阶梯系数1.5）
- 用户数：600人（阶梯系数1.5）

计算：
```
财务管理模块工作量 = 15 × 1.3 × 1.5 × 1.5 = 43.875人天
供应链管理模块工作量 = 20 × 1.5 × 1.5 × 1.5 = 67.5人天
核心迁移工作量 = 43.875 + 67.5 = 111.375人天
```

##### 2. 报表工作量

**计算公式**：
```
报表工作量 = 报表数量 × 报表系数
```

**计算逻辑**：
- 报表数量：用户录入
- 报表系数：从系统配置获取（单位：人天/个）

**计算示例**：
```
报表数量：50个
报表系数：0.5人天/个
报表工作量 = 50 × 0.5 = 25人天
```

##### 3. 客开工作量

**计算公式**：
```
客开工作量 = 客开评估人天数（手动输入）
```

**计算逻辑**：
- 如果有客开，用户手动录入客开人天数
- 如果没有客开，客开工作量为0

**计算示例**：
```
客开工作量 = 20人天（手动输入）
```

##### 4. 总工作量汇总

**计算公式**：
```
总工作量 = 核心迁移工作量 + 报表工作量 + 客开工作量
```

**计算示例**：
```
总工作量 = 111.375 + 25 + 20 = 156.375人天
```

**结果展示**：
- 显示总工作量（保留2位小数）
- 显示各部分工作量明细
- 显示各模块工作量明细

### 3.4 工作量统计展示模块

#### 3.4.1 多维度统计分析
**业务场景**：用户需要从多个维度查看工作量分布情况。

**统计维度**：

##### 1. 按模块统计
- 各模块工作量占比（饼图）

- 显示每个模块的工作量和占比

- 核心迁移工作量 vs 报表工作量 vs 客开工作量的占比（饼图）

- 显示数据量阶梯信息
- 显示用户数阶梯信息
- 高复杂度模块提示

##### 4. 总体汇总
- 总工作量（人天）
- 预估工期建议（根据工作量换算）
- 关键指标概览（模块数、数据量、用户数、报表数）

#### 3.4.2 可视化展示
**业务场景**：通过图表直观展示工作量分布。

**图表类型**：
- **饼图**：工作量类型分布、模块工作量占比
- **柱状图**：模块工作量对比
- **雷达图**：多维度评估指标（数据量、用户数、模块数、报表数、客开等）

**交互功能**：

## 五、业务规则

### 5.1 系统规则
1. 源系统和目标系统不能相同
2. 项目名称不能重复
3. 项目至少选择一个模块
4. 工作量计算保留2位小数

### 5.2 状态规则
1. 项目状态流转：草稿 → 进行中 → 已完成 → 已归档
2. 只有草稿状态的项目可以删除
3. 已归档的项目为只读状态，不可修改

### 5.3 计算规则
1. 未调整系数的模块使用默认系数
2. 数据量和用户数根据阶梯自动匹配系数
3. 无客开时，客开工作量为0
4. 总工作量 = 核心迁移工作量 + 报表工作量 + 客开工作量

### 5.4 配置规则
1. 被项目引用的系统类型、模块不能删除
2. 阶梯配置至少保留一个
3. 系数可以为小数，支持小于1或大于1

## 六、约束与假设

### 6.1 业务约束
- 系统仅支持一对一的ERP系统升迁评估，不支持多系统组合升迁
- 工作量评估模型为预设模型，用户在项目级别可调整模块系数
- 数据清洗需求不计入工作量计算，仅作为参考信息

### 6.2 技术约束
- 系统为Web应用，需支持主流浏览器
- 系统需支持数据导出功能

### 6.3 假设条件
- 假设用户提供的评估数据准确
- 假设工作量评估模型合理有效
- 假设模块库配置完善
