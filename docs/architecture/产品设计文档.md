## 一、领域模型设计（DDD）

### 1.1 领域划分

根据业务需求，系统分为以下领域：

#### 1.1.1 配置域（Configuration Domain）
负责系统基础配置数据的管理，为评估域提供基础数据支撑。

**核心实体**：
- **系统类型（SystemType）**：ERP系统类型信息
- **模块（Module）**：ERP系统模块及配置
- **数据量阶梯（DataVolumeLadder）**：数据量分段标准
- **用户数阶梯（UserCountLadder）**：用户数分段标准
- **报表配置（ReportConfig）**：报表系数配置

#### 1.1.2 项目域（Project Domain）
负责评估项目的生命周期管理。

**核心实体**：
- **项目（Project）**：评估项目聚合根
- **项目状态（ProjectStatus）**：项目状态枚举

#### 1.1.3 评估域（Evaluation Domain）
负责工作量评估的核心业务逻辑。

**核心实体**：
- **评估（Evaluation）**：评估聚合根
- **评估指标（EvaluationIndicator）**：各项评估指标值对象
- **模块配置（ModuleConfiguration）**：项目级别的模块配置
- **工作量（Workload）**：工作量计算结果值对象
- **工作量明细（WorkloadDetail）**：工作量计算明细

#### 1.1.4 报告域（Report Domain）
负责评估报告的生成和输出。

**核心实体**：
- **报告（Report）**：评估报告
- **报告章节（ReportSection）**：报告组成部分

#### 1.1.5 用户域（User Domain）
负责用户身份认证和权限管理。

**核心实体**：
- **用户（User）**：用户账号
- **角色（Role）**：用户角色

### 1.2 聚合设计

#### 聚合1：系统配置聚合
```
系统类型（聚合根）
  └─ 模块（实体）
```

#### 聚合2：项目评估聚合
```
项目（聚合根）
  ├─ 模块配置（实体）
  └─ 评估（实体）
       └─ 工作量明细（值对象）
```

#### 聚合3：阶梯配置聚合
```
数据量阶梯（聚合根，独立）
用户数阶梯（聚合根，独立）
报表配置（聚合根，独立）
```

### 1.3 领域服务

#### 1.3.1 工作量计算服务（WorkloadCalculationService）
**职责**：根据评估指标计算工作量

**核心方法**：
- `calculateCoreMigrationWorkload()`：计算核心迁移工作量
- `calculateReportWorkload()`：计算报表工作量
- `calculateTotalWorkload()`：计算总工作量

#### 1.3.2 阶梯匹配服务（LadderMatchingService）
**职责**：根据数据值匹配对应阶梯

**核心方法**：
- `matchDataVolumeLadder(dataVolume)`：匹配数据量阶梯
- `matchUserCountLadder(userCount)`：匹配用户数阶梯

#### 1.3.3 报告生成服务（ReportGenerationService）
**职责**：生成评估报告

**核心方法**：
- `generateReport(projectId, format)`：生成指定格式的报告

### 1.4 领域事件

- **项目创建事件（ProjectCreatedEvent）**：项目创建后触发
- **评估完成事件（EvaluationCompletedEvent）**：评估完成后触发
- **报告生成事件（ReportGeneratedEvent）**：报告生成后触发

#### 3.1.2.1 模块库分页（2026-06-09 追加）

**触发问题**：随着业务积累，模块库数据量会从几十条增长到几百上千条；当前一次性全量加载渲染会导致浏览器卡顿、接口响应体过大。本节定义分页交互规范。

**页面布局（修订）**：

```
┌──────────────────────────────────────────────────────────┐
│  模块库管理                          [+ 新增模块]          │
├──────────────────────────────────────────────────────────┤
│  模块名称：[搜索框]  所属系统：[全部 ▼]  状态：[全部 ▼]   │
│                                                          │
│  ┌──────────────────────────────────────────────────────┐│
│  │ 模块名称 │ 所属系统 │ 基础人天 │ 默认系数 │ 状态 │ 操作 ││
│  ├──────────────────────────────────────────────────────┤│
│  │ 财务管理 │ SAP     │ 15.00   │ 1.20    │ 启用 │ [编辑][禁用][删除] ││
│  │ ...     │ ...     │ ...     │ ...     │ ... │ ...               ││
│  └──────────────────────────────────────────────────────┘│
│                                                          │
│  共 X 条  [10条/页 ▼]  [首页] [<] 1 2 3 [>] [末页] [跳 X]│
└──────────────────────────────────────────────────────────┘
```

**分页组件行为**（基于 Element Plus `el-pagination`）：

| 元素 | 行为 |
|------|------|
| 共 X 条 | 显示当前筛选条件下的总记录数，由后端返回 |
| pageSize 选择器 | 下拉选择，可选 10/20/50/100；选择后立即重新查询，pageNum 重置为 1 |
| 首页按钮 | 点击跳 pageNum=1 |
| 上一页按钮 | pageNum > 1 时可点；点击 pageNum - 1 |
| 下一页按钮 | pageNum < totalPages 时可点；点击 pageNum + 1 |
| 末页按钮 | 点击跳 pageNum=totalPages |
| 页码跳转 | 输入数字后回车跳转到指定页；超出范围（< 1 或 > totalPages）不响应，提示"页码超出范围" |
| 当前页高亮 | 当前 pageNum 在页码列表中加 active class |

**边界行为**：

| 场景 | UI 表现 | 后端行为 |
|------|---------|----------|
| 0 条数据 | 表格显示空状态"暂无数据，请先新增模块"；分页器"共 0 条"但不可翻页 | 返回 total=0, records=[] |
| 数据 < pageSize | 仅第 1 页有数据，翻页按钮 disabled | 正常返回 |
| pageNum > totalPages | 自动重定向到最后一页（前端改 pageNum 触发重新查询） | 后端仍按传入 pageNum 查，返回空 records + 正确 total |
| 改筛选条件 | 自动重置 pageNum=1 再查 | 不变 |
| 改 pageSize | 自动重置 pageNum=1 再查 | 不变 |
| 网络失败 | 表格保持上一页数据 + ElMessage 错误 toast | — |

**接口契约**（前后端必须一致）：
- 请求：`GET /api/modules?pageNum=1&pageSize=10&moduleName=xxx&systemId=1&category=HR&status=1`
- 响应：`{ records: [...], total: 25, pageNum: 1, pageSize: 10, totalPages: 3, hasPrevious: false, hasNext: true, fromIndex: 1, toIndex: 10 }`
- 排序：固定按 `id` 升序（不暴露给用户配置，避免翻页数据跳变）

**E2E 验收要点**：
- 数据为 0 时表格+分页器渲染
- 数据 ≥ 1 页时翻页按钮可点
- 翻页后筛选条件不丢
- 改 pageSize 立即重新查询
