## 一、设计概述

### 1.1 设计原则

| 原则 | 说明 |
|------|------|
| 规范化设计 | 遵循数据库第三范式 (3NF)，减少数据冗余 |
| 命名规范 | 采用小写下划线命名法，见名知意 |
| 字段设计 | 根据数据特性选择合适的数据类型和长度 |
| 索引优化 | 针对查询字段建立适当索引，提高查询性能 |
| 扩展性 | 预留扩展字段，便于后续功能迭代 |

### 1.2 命名规范

```sql
-- 数据库名称
migrametric

-- 表命名规范
-- 前缀规则：
-- sys_     : 系统配置相关表（system）
-- proj_    : 项目相关表（project）
-- eval_    : 评估相关表（evaluation）
-- rpt_     : 报告相关表（report）

-- 字段命名规范
-- 主键：id
-- 外键：xxx_id
-- 创建时间：create_time
-- 更新时间：update_time
-- 状态：status
-- 名称：xxx_name
-- 数量：xxx_count
-- 金额/工作量：xxx_amount / xxx_workload
```

### 1.3 字段类型选择规范

| 数据类型 | 使用场景 | 示例 |
|---------|---------|------|
| BIGINT | 主键、关联ID | `id BIGINT UNSIGNED` |
| VARCHAR(n) | 短文本、名称 | `username VARCHAR(50)` |
| TEXT | 长文本、描述 | `description TEXT` |
| INT | 整数、小数量 | `table_count INT` |
| DECIMAL(p,s) | 金额、系数、精确数值 | `workload DECIMAL(10,2)` |
| TINYINT | 状态、枚举值 | `status TINYINT` |
| DATETIME | 日期时间 | `create_time DATETIME` |
| DATE | 日期 | `evaluation_date DATE` |

## 四、表结构详解

### 4.1 用户域表

#### 4.1.1 sys_user - 用户表

```sql
-- ============================================
-- 用户表
-- 存储系统用户信息
-- ============================================
CREATE TABLE sys_user (
    -- 主键
    id                  BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '用户ID',

    -- 用户信息
    username            VARCHAR(50)     NOT NULL COMMENT '用户名（登录账号）',
    password            VARCHAR(200)    NOT NULL COMMENT '密码（BCrypt加密）',
    user_name           VARCHAR(50)     NOT NULL COMMENT '用户姓名',
    email               VARCHAR(100)             DEFAULT NULL COMMENT '邮箱',
    phone               VARCHAR(20)              DEFAULT NULL COMMENT '手机号',
    avatar              VARCHAR(500)             DEFAULT NULL COMMENT '头像URL',

    -- 用户角色
    role                VARCHAR(20)     NOT NULL DEFAULT 'USER' COMMENT '角色：ADMIN-系统管理员，USER-普通用户',

    -- 状态
    status              TINYINT        NOT NULL DEFAULT 1 COMMENT '状态：0-禁用，1-启用',

    -- 时间信息
    create_time         DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time         DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    last_login_time     DATETIME                 DEFAULT NULL COMMENT '最后登录时间',

    -- 审计字段
    create_by           VARCHAR(64)              DEFAULT NULL COMMENT '创建者',
    update_by           VARCHAR(64)              DEFAULT NULL COMMENT '更新者',
    remark              VARCHAR(500)             DEFAULT NULL COMMENT '备注',

    -- 约束
    PRIMARY KEY (id),
    UNIQUE KEY uk_username (username),
    KEY idx_status (status),
    KEY idx_role (role),
    KEY idx_create_time (create_time)

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='用户表';
```

**字段说明：**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 用户唯一标识，自增主键 |
| username | VARCHAR(50) | 用户名，登录账号，唯一约束 |
| password | VARCHAR(200) | BCrypt加密后的密码，长度200足够 |
| user_name | VARCHAR(50) | 用户真实姓名 |
| email | VARCHAR(100) | 邮箱地址，可为空 |
| phone | VARCHAR(20) | 手机号，可为空 |
| avatar | VARCHAR(500) | 头像URL地址 |
| role | VARCHAR(20) | 角色代码：ADMIN/SUPER_ADMIN |
| status | TINYINT | 状态：0-禁用，1-启用 |
| create_time | DATETIME | 创建时间 |
| update_time | DATETIME | 更新时间 |
| last_login_time | DATETIME | 最后登录时间 |
| create_by | VARCHAR(64) | 创建者 |
| update_by | VARCHAR(64) | 更新者 |
| remark | VARCHAR(500) | 备注信息 |

##### 4.2.2.1 sys_module 分页索引利用（2026-06-09 需求：§3.1.10）

**目的**：模块库分页查询时的高效索引利用说明（表结构本身不变，仅文档化现有索引的查询路径）。

**索引清单**（已存在 DDL 中，见 §4.2.2 line 590-592）：

| 索引名 | 字段 | 类型 | 用途 |
|--------|------|------|------|
| `PRIMARY KEY (id)` | id | 主键 | `LIMIT ?, ?` 翻页定位 |
| `idx_create_time` | create_time | NORMAL | `ORDER BY create_time DESC` 排序 |
| `idx_system_id` | system_id | NORMAL | 筛选 `WHERE system_id = ?` |
| `idx_status` | status | NORMAL | 筛选 `WHERE status = ?`（0=禁用 / 1=启用） |
| `idx_category` | category | NORMAL | 筛选 `WHERE category = ?`（模块分类） |

**分页查询路径**（`ModuleServiceImpl.queryPage` → `moduleMapper.selectPage(page, wrapper)` → MyBatis-Plus 自动生成 SQL）：

| 场景 | SQL 模式 | 索引利用 |
|------|----------|----------|
| 无筛选 + 翻页 | `WHERE deleted=0 ORDER BY create_time DESC LIMIT ?,?` | `idx_create_time` 反向扫描 |
| 按 systemId 筛选 | `WHERE system_id=? AND deleted=0 ORDER BY create_time DESC LIMIT ?,?` | `idx_system_id` 过滤后排序 |
| 按 status 筛选 | `WHERE status=? AND deleted=0 ORDER BY create_time DESC LIMIT ?,?` | `idx_status` 过滤后排序 |
| 按 moduleName 模糊 | `WHERE module_name LIKE '%xxx%' AND deleted=0 ORDER BY create_time DESC LIMIT ?,?` | 全表扫描（**前缀模糊不走索引**），千级数据可控 |
| 组合筛选 | `WHERE system_id=? AND status=? AND category=? AND deleted=0 ORDER BY create_time DESC LIMIT ?,?` | 走最严格条件对应索引 + 回表过滤 |

**软删除**：`sys_module.deleted` 字段（`TINYINT NOT NULL DEFAULT 0`），由 MyBatis-Plus `@TableLogic` 自动加 `WHERE deleted=0` 条件，**不需要在 wrapper 显式写**。

**分页 SQL 形式**（MyBatis-Plus 自动生成）：

```sql
-- 无筛选
SELECT id, module_name, system_id, category, base_workload, default_weight,
       description, status, create_time, update_time, create_by, update_by
  FROM sys_module
 WHERE deleted = 0
 ORDER BY create_time DESC
 LIMIT 0, 10;  -- (pageNum-1) * pageSize, pageSize

-- 带筛选
SELECT ...
  FROM sys_module
 WHERE deleted = 0 AND system_id = 1 AND status = 1
 ORDER BY create_time DESC
 LIMIT 10, 10;  -- 第 2 页
```

**Count SQL**（`SELECT COUNT(*) FROM sys_module WHERE ...`）走同样索引。

**性能预期**（基于当前 dev 库数据量）：

| 数据量 | 单次 queryPage 耗时（含 COUNT） | 备注 |
|--------|--------------------------------|------|
| < 100 条 | < 10ms | 全在 1 页，pageSize=10 |
| 100-1000 条 | 10-50ms | 翻页正常 |
| 1000-10000 条 | 50-200ms | moduleName 模糊查询可能略慢，`ORDER BY create_time DESC` filesort |
| > 10000 条 | 待压测 | 建议加 `idx_create_time` 索引 + `idx_module_name` 走前缀索引 |

**未来优化**（TBD，本期不做）：
- 如 moduleName 模糊查询占比 > 30%，考虑：
  1. 加 `idx_module_name(module_name)`（只支持前缀 `LIKE 'xxx%'`，不解决 `%xxx%` 场景）
  2. 引入全文索引（FULLTEXT）或 Elasticsearch
  3. 限制 `moduleName` 模糊查询的最大结果数（> 1000 提示用户用精确筛选）
- 如 `ORDER BY create_time DESC` 在万级后明显慢，加 `idx_create_time(create_time)` 索引
  - 注意：单列索引对 `WHERE system_id=? ORDER BY create_time DESC LIMIT ?,?` 不生效（不同字段），需用 `idx_system_create(system_id, create_time)` 联合索引

**N/A**：本期不改表结构、不加索引、不动 DDL。

```
模块工作量 = 基础人天 × 加权系数 × 数据量阶梯系数 × 用户数阶梯系数
```
